# 学生体验、教师复盘与调整

轮末、学生要求复盘或重要中途反馈出现时读取。复盘依据当前课程对话、作品与验收，不借用旧项目的教师评价或学生偏好。

## 收集学生体验

先复述已经表达的体验，避免重复询问。用少量问题了解最关键的缺口，例如：

- 哪个环节帮助你理解了，哪个仍不清楚？
- 节奏、任务大小和提示方式有什么需要改变？
- 下一轮想按原方向继续，还是调整关注点？

允许学生自由回答，不要求每轮填完整问卷。反馈是学生的主观体验，照实标注来源和日期；不要改写为教师替学生认定的学习效果。学生称“懂了”值得记录，但不能单凭这句话通过实作标准。

没有收到反馈时保存为 `awaiting_feedback` 并邀请补充，不虚构满意或无异议。明确不想反馈则记 `skipped_by_student`；之后可补记。遇到暂停，只完成现有记录，不开启下轮。

## 复盘内容

每轮复盘包含：

1. 本轮目标、实际完成、证据与能力边界；帮助程度、未完成项及暂缓事项。
2. 学生体验：原话或忠实摘要、时间、来源；未收到则明确标记。
3. 教师观察：哪些安排有效，哪些具体行为造成了困惑、重复或负担；观察与推测分开。
4. 调整清单：反馈来源 → 当前解释 → 具体改变 → 影响范围 → 是否需确认 → 在下轮怎样观察效果。
5. 下一轮建议或当前断点；不能把建议写成已批准计划。

中途复盘标“进行中”；已有复盘追加带日期的更新，不抹掉此前状态。出现冲突时保留修正过程，将最新明确生效的规则同步到当前状态。

## 让反馈实际生效

例：“任务太碎，不知道这些修改为了什么。”

对应调整：下轮先展示完整数据流和可用成果，把若干单行修改合为一个小功能；仍在遇到卡点时解释语法。下轮复盘再询问目的是否清楚、任务大小是否合适。

例：“想先理解原理，不急着做完整作品。”

对应调整：提出以解释、手算或小实验为主的路线版本，说明哪些作品任务暂缓；经学生确认后改变范围，不擅自降低原定实作标准来宣布通过。

每次调整都有来源与生效范围。仅对某次任务的偏好不要泛化为永久规则。提议、已确认、生效和已被取代分别记录；临时例子或提示调整可当场执行，改变目标、必需验收和路线的调整需确认。

在下一轮计划中展示最相关的“反馈 → 本轮改变 → 理由”；不只写“已阅读复盘”。下一轮结束再检查改变是否有效。
